# 临时备份指定数据库

适用于项目发布、数据修复或其他操作前，只需备份某个实例中少数数据库的情况。

## 操作步骤

1. 打开数据库实例详情，点击 **临时备份**；实例列表的操作菜单也提供此入口。
2. 选择一条现有备份配置。只有一条配置时自动选中；多条时须自行选择。
   本次备份沿用该配置的存储目标、存储路径及保留规则，并使用当前压缩设置。
3. 在数据库列表搜索并勾选一个或多个数据库。可选择日常策略排除或正则不匹配的用户库。
   搜索仅过滤显示内容，不会清空已勾选的其他数据库；系统库不出现在列表中。
4. 可填写备注，例如“某项目发布前备份”。有快照锁定权限时，可勾选 **保护此次备份**。
5. 点击 **开始临时备份**。到快照页面查看每个库的执行状态、日志和文件。
   提交成功仅表示进入任务队列；请确认快照成功完成后再进行项目操作。

## 行为与权限

- 仅此次执行，不增加定时配置，不修改现有数据库范围、排除列表或正则表达式。
- 每个数据库生成独立快照，标记为“临时备份”，记录操作人和备注。
  沿用已有下载、恢复及失败重备入口；重备仍只针对原库。
- 需要“执行备份”权限，Viewer 不能执行；保护快照额外需要快照锁定权限。
  重新执行受保护的失败临时快照也需要锁定权限。
- 提交时重新校验可用数据库；库已删除或不再可访问时，须刷新并重新选择。
- 同实例、同库已有等待中或执行中的备份时，拒绝整个提交并列出冲突库，
  即使正在运行的任务来自另一条备份配置。不同库可以正常提交。
- 默认不保护快照，随原配置正常清理，也参与 GFS 保留轮换。
  受保护快照需手动解除锁定后才会参与自动清理，长期保留会持续占用存储空间。
- 不增加 Worker；按原队列并发运行，与定时任务共享现有资源。

## 支持范围

支持直连及 SSH 隧道下的 MySQL/MariaDB、PostgreSQL、SQL Server 和 MongoDB 用户库。
SQLite、Firebird 从实例已有配置中的文件路径选择，不允许临时输入任意新路径。

Agent 实例暂不支持此选库入口，界面会明确提示。
Redis/Valkey 的快照包含整个实例，无法用此功能只备份一个逻辑库，请使用“立即备份”。

数据库列表获取失败时明确报错，不会自动改成“备份所有库”。任务投递失败会留下失败快照与日志，
便于排查后重新备份。
